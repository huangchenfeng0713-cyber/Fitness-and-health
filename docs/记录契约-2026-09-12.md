# 后续记录契约（2026-09-12）

这是《Fitness-and-health-最终建议》批次 2 的字段决策，**尚未启用新持久化字段或自动校正**。批次 0/1 的现行行为见《算法依据》。不增加第二份原始摄入、体重或训练事实源。

## 日级饮食完整度

放在现有按日状态中，与 diet 条目引用同一本地日历日期，拟用独立的 `dietLogStatus`：`unknown`（默认/旧记录）、`partial`（用户确认漏记）、`complete`（用户确认全天记录完整）。无条目是“没有记录”，并非 0 kcal；只有完整度明确且有可解释记录时才允许后续算法评估零摄入。修改状态记录确认时间和来源，撤销确认回到 unknown。

营养 `coverage.kcal.complete` 只代表已记录条目的热量字段齐全，绝不推导 dietLogStatus。后续删除或新增条目时，需要决定是否让旧确认失效；第一版应将日级完整确认降回 unknown，避免编辑后沿用未经确认的全天状态。模板/复制仅复制食物，不复制某天“完整”的声明。

## 训练组

继续扩展 `training.items[].sets`；既有 id 和日期不重建。后续要一次贯通 normalizeSession、saveTraining、统计、导出、导入、账号快照和恢复测试，不能只增加输入框。

| 字段 | 决定的语义 | 旧记录处理 |
| --- | --- | --- |
| reps | 有限非负次数；null 未知 | 不把 null/空白改成 0；原有 0 保留，不能判定完成 |
| weightKg | 原始重量；null 未知，0 显式零 | 原值保留；以前被清洗为 0 的缺失不能反推 |
| completed | 显式确认完成状态，草稿 false | 缺字段为 legacy-unknown；按既有 reps/done 规则展示“已记录”，不改称已确认工作组 |
| rir | 可选、非负、产品输入上限另行确定；null 未知 | 不默认 2/3，不复制上一组 RIR |
| setType | warmup / work / unknown | 一律 unknown，不根据重量/位置猜热身 |
| durationSeconds | 可选非负秒数，支持计时动作 | 未填保持 null；不从次数猜时长 |
| loadMode | unknown / bodyweight / external / assistance / machine | 未注明则 unknown，不靠动作名猜实际公斤口径 |
| loadConvention | 原始公斤为单手 / 双手合计 / 器械刻度等，可选 | 未注明则 unknown，不默认为单手或总重 |

bodyweight 指用户明确记录的自重方式，额外负重、辅助负重单独标明；不自动乘体重系数。器械刻度不保证等于实际阻力。未知/辅助/不同器械汇总不解释为净做功、运动热量或可比较负荷。

本轮草稿暂仅存在页面内存，尚不需要 completed 落库；确认按钮写入真实组。将来若保存跨刷新草稿，必须首先实现上述完成状态过滤，不能让非空 reps 的草稿进入统计。

工作组数只纳入明确完成且 setType=work；热身单列，旧未知组单列而不是丢弃。训练日/记录组数与工作组数是不同统计。RIR ≤ 3 若作“接近力竭”产品筛选，应明确是操作规则，不是唯一有效训练的生理界线。主练直接组与协同参与分开展示，不统一折半；细分区域不能在大肌群统计重复累加。

## 周期反馈边界（批次 3，未实现）

保持当前固定计划，先做建议、后做自愿开启的自动采用。评估仅用已结束日，要求可核对的饮食完整度、配对设备日及多周体重记录；阈值作为产品设置接受回归，不宣称科学定值。无足够证据返回“保持并继续记录”。若生成新计划，复用 targetVersions，未来生效，不回写旧日；长时间未使用不补跑多轮。暂不增加卡尔曼/RTS、徒手等效公斤或个人真实维持热量的确定估计。

## 实施前必须通过的契约测试

1. 新字段从编辑到清洗、持久化、JSON 往返、账号模拟上传下载都保持；未知字段/原始旧值不被无声覆盖。
2. 草稿/热身/工作/未知四类样本，分别核对记录日、总记录组、工作组、主练与协同。
3. 摄入有记录但明确 partial 不可成为校准完整日；营养字段完整不能绕过日级门槛。
4. 固定样本验证跨日、时区和目标生效边界；新目标不改旧图/旧日解释。
5. 真实 iPhone 快捷指令与多设备账号流程在隔离测试账号验证，测试数据不能混入用户真实记录。
