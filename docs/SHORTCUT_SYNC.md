# iPhone 快捷指令自动同步（详细设置）

v1.6.0 起，快捷指令可以把 Apple 健康数据直接写入当前登录账号，不再需要复制粘贴 JSON，网页也不必保持打开。

数据链路是：

`Apple 健康 → iPhone 快捷指令 → 专属上传 URL → 当前账号 → 网页自动读取`

建议先只同步步数、活动能量和静息能量，确认成功后再逐项增加其他指标。这样某个健康类型没有权限或没有样本时，更容易定位问题。

最快的配置路径是：在网页生成连接信息后点击 **复制基础配置**，再在 iPhone 上点击 **新建**。网页会通过 Apple 官方的 `shortcuts://create-shortcut` 地址直接打开快捷指令编辑器；基础配置只列出推荐的三个指标，先跑通后再按本文增加高级字段。

## 一、在网页生成连接信息

1. 用 Safari 打开应用并登录自己的账号。
2. 进入 **数据 → 数据管理 → 快捷指令自动上传**。
3. 设备名称填写容易辨认的名称，例如“我的 iPhone 15”。
4. 点击 **生成连接信息**。
5. 分别复制并妥善保存：
   - **上传 URL**；
   - **设备令牌**。

设备令牌只显示一次，作用相当于这台 iPhone 的上传密码。不要把它放进 URL、截图、聊天记录或公开仓库。令牌丢失时，在网页撤销旧设备并重新生成即可。

## 二、新建快捷指令

打开 iPhone 的 **快捷指令** App，进入 **快捷指令**，点击右上角 **+**，名称改为“健康饮食自动同步”。不同 iOS 版本的动作名称可能略有差异，可以在“添加操作”的搜索框里搜索下列粗体文字。

### 1. 建立日期变量

依次添加：

1. **当前日期**。
2. **格式化日期**，日期选择“当前日期”，格式选择“自定”，格式字符串填写 `yyyy-MM-dd`。
3. **设定变量**，命名为 `同步日期`。
4. 再添加一次 **格式化日期**，日期仍选“当前日期”，自定格式填写 `yyyy-MM-dd'T'HH:mm:ssXXX`。
5. **设定变量**，命名为 `采集时间`。

在中国大陆，最终时间应类似 `2026-08-26T12:18:58+08:00`。不要只把 `2026-08-26` 同时当作时间戳。

### 2. 读取“今天累计到现在”的指标

以下指标都属于当天累计值。每个指标重复执行这一组操作：

1. 添加 **查找健康样本**。
2. 健康类型选择对应项目。
3. 筛选条件选择“开始日期在今天”。
4. 添加 **计算统计数据**，统计方式选择 **总和**。
5. 如界面提供单位转换，把结果转换为下表要求的单位。
6. 添加 **从输入中获取数字**（或在下一步直接使用统计结果）。
7. 添加 **设定变量**，使用下表中的变量名。

| Apple 健康项目 | 快捷指令变量 | JSON 键 | 单位 |
| --- | --- | --- | --- |
| 步数 | 今日步数 | `steps` | 步 |
| 活动能量 | 今日活动能量 | `activeEnergyKcal` | kcal |
| 静息能量 | 今日静息能量 | `restingEnergyKcal` | kcal |
| 锻炼时间 | 今日锻炼分钟 | `exerciseMinutes` | 分钟 |
| 站立时间 | 今日站立分钟 | `standMinutes` | 分钟 |
| 步行 + 跑步距离 | 今日距离 | `distanceKm` | km |

如果某项没有样本或没有读取权限，用 **如果** 判断并且**不要把该键加入上传字典**；不要用 `0` 代替缺失值，否则晚一次运行可能用假 0 覆盖同一天早先的有效数据。这些数值必须是“今天截至现在的总数”：例如 12:00 是 2,000 步、18:00 是 6,000 步，服务器会用 6,000 覆盖 2,000；不要在快捷指令中再把它们相加，否则会重复计算。

### 3. 可选：读取最新体重、体脂、静息心率和最大摄氧量

这些是单次测量，不要计算总和，也不要把旧体重伪装成今天的新测量。每一项使用：

1. **查找健康样本**，健康类型选择对应项目。
2. 排序选择“开始日期”，顺序选择“最新优先”，限制设为 `1` 条。
3. 用 **计数** 或 **如果** 检查确实找到了样本。
4. 取得该样本的数值，并转换到下表单位。
5. 再用 **获取健康样本的详细信息** 取得该样本的“开始日期”。
6. 把测量日期格式化为 `yyyy-MM-dd'T'HH:mm:ssXXX`。

| Apple 健康项目 | 数值键 | 测量时间键 | 单位 |
| --- | --- | --- | --- |
| 体重 | `weightKg` | `weightMeasuredAt` | kg |
| 体脂率 | `bodyFatPct` | `bodyFatMeasuredAt` | 百分数，例如 18.5 |
| 静息心率 | `restingHR` | `restingHRMeasuredAt` | bpm |
| 最大摄氧量 | `vo2max` | `vo2maxMeasuredAt` | ml/kg/min |

只有找到样本时才把相应字段加入字典。没有体重时请省略 `weightKg`，不要发送 `weightKg: 0`。
（如果确实漏传了 `0`，服务端会把它当成「今天没有样本」跳过而不是报错——活人的体重、体脂率、
静息心率和最大摄氧量不可能是 `0`，而快捷指令的空数值链只能产出 `0`。但仍建议用 **如果** 省略该键，
这样返回里的 `skipped` 才只包含真正需要关注的项。）每个单次测量值都必须同时带对应的测量时间；服务端会拒绝缺少 `measuredAt` 的请求，以免把旧体重伪记成今天。测量时间字段可以让服务器把旧测量归回真实日期，避免每次自动化都生成一条假体重。

### 4. 可选：睡眠

睡眠分析可能同时包含“卧床”“清醒”“核心睡眠”“深度睡眠”“快速眼动”，还可能来自 iPhone、Apple Watch 和第三方 App。把所有样本时长直接求和，容易把一晚睡眠算两遍。

初次配置建议暂不上传 `sleepMinutes`。需要同步时，只统计明确的睡眠阶段，排除“卧床”和“清醒”，并固定一个主要来源；如果无法在快捷指令里排除重叠，使用 Apple 健康完整导出让网页统一去重更稳妥。

## 三、组装上传字典

添加 **字典** 操作，键名必须使用英文半角字符。先放入下列固定字段和已经取得的数值：

| 键 | 类型 | 值 |
| --- | --- | --- |
| `protocolVersion` | 数字 | `1` |
| `timestamp` | 文本 | 变量“采集时间” |
| `date` | 文本 | 变量“同步日期” |
| `timezone` | 文本 | `Asia/Shanghai` |
| `source` | 文本 | `apple_shortcuts` |
| `steps` | 数字 | 变量“今日步数” |
| `activeEnergyKcal` | 数字 | 变量“今日活动能量” |
| `restingEnergyKcal` | 数字 | 变量“今日静息能量” |
| `exerciseMinutes` | 数字 | 变量“今日锻炼分钟” |
| `standMinutes` | 数字 | 变量“今日站立分钟” |
| `distanceKm` | 数字 | 变量“今日距离” |

再用 **如果找到了样本 → 设定字典值**，有选择地加入 `weightKg`、`weightMeasuredAt` 等单次测量字段。不要把可选字段留成空文本或 `0`。

完整请求的形状大致如下；示例数字只用于核对结构，不要直接写死：

```json
{
  "protocolVersion": 1,
  "timestamp": "2026-08-26T12:18:58+08:00",
  "date": "2026-08-26",
  "timezone": "Asia/Shanghai",
  "source": "apple_shortcuts",
  "steps": 1594,
  "activeEnergyKcal": 103.21,
  "restingEnergyKcal": 791.67,
  "exerciseMinutes": 3,
  "standMinutes": 36,
  "distanceKm": 1.113,
  "weightKg": 59,
  "weightMeasuredAt": "2026-08-26T07:35:00+08:00",
  "restingHR": 70,
  "restingHRMeasuredAt": "2026-08-26T06:20:00+08:00"
}
```

## 四、把字典 POST 到网页接口

1. 添加 **URL** 操作，把网页生成的“上传 URL”粘贴进去。
2. 添加 **获取 URL 内容**，URL 选择上一步的 URL。
3. 展开“显示更多”：
   - 方法：`POST`；
   - 请求体：`JSON`；
   - JSON 内容：选择上一步的“字典”变量；某些 iOS 版本会要求在这里重新添加字典各字段，按第三节逐项添加即可。
4. 在“标头”中添加：
   - `Content-Type` → `application/json`；
   - `X-Health-Sync-Token` → 粘贴网页生成的设备令牌。
5. 可在最后添加 **快速查看** 或 **显示结果**，用于第一次调试。确认成功后可以删除这个显示动作，避免自动化每次弹窗。

设备令牌必须放在请求标头中，不能放到 JSON、URL 查询参数或普通文本动作里。

## 五、先手动测试一次

1. 在快捷指令编辑页点击右下角运行按钮。
2. 首次运行时，允许它读取所需的健康类型并访问上传域名。
3. 成功响应应包含：

```json
{"ok":true,"applied":true,"date":"2026-08-26",
 "stored":["steps","activeEnergy","restingEnergy"],"skipped":["restingHR"],"rejected":[]}
```

- `stored` —— 真正写进账号的字段。
- `skipped` —— 今天还没有样本的字段（快捷指令传上来是 `0`）。静息心率最常见：
  Apple Watch 通常要等夜间睡眠之后才算得出当天的值，白天运行取不到属于正常。
- `rejected` —— 数值超出生理范围、被单独挑掉的字段。

**这三项都不影响同一次上传里其余字段入库。** 只有当一个有效指标都不剩时才会返回 400。

4. 返回网页 **数据 → 数据管理 → 快捷指令自动上传**，点击 **立即读取账号最新数据**。
5. 检查“最近上传”和今天的步数、能量是否更新。

`applied: false` 表示账号中已经有更新的同日累计值，因此安全忽略了这次较旧上传；`duplicate: true` 表示完全相同的请求已处理过。这两种情况都不代表同步故障。

## 六、设置定时自动运行

1. 打开 **快捷指令 → 自动化**。
2. 点击右上角 **+**，选择 **创建个人自动化**（有些版本会直接进入触发器列表）。
3. 选择 **特定时间**。
4. 选择一个时间，例如 `08:00`，重复选择 **每天**。
5. 选择 **立即运行**；若界面显示“运行前询问”，将它关闭。
6. 下一步选择 **运行快捷指令**，指定“健康饮食自动同步”。
7. 保存，并按相同步骤增加其他时间。

建议建立 `08:00`、`12:00`、`18:00`、`22:00`、`23:50` 五个自动化。iOS 的“特定时间”触发器没有“一次设置、每小时重复”的选项；若坚持每小时同步，需要为每个小时各建一个自动化。健康趋势通常不需要这么密集，4～5 次/天更省电，也足以保持数据新鲜。

iOS 可能因省电模式、关机、权限或系统调度稍晚执行，并不保证严格在整点完成。快捷指令上传直接进入账号：网页可以关闭；再次打开、切回前台或在使用期间，网页会读取最新数据，也可以手动点击“立即读取账号最新数据”。

## 七、常见问题

| 现象或返回码 | 处理方法 |
| --- | --- |
| `invalid_token` | 设备令牌填写错误、包含多余空格或设备已撤销；重新复制，必要时生成新连接。 |
| `invalid_json` / `invalid_payload` | 请求体必须选 JSON；检查是否误用了中文弯引号，或把整段 JSON 当成普通文本发送。 |
| `no_metrics` | 字典里没有任何有效健康数值；先只保留步数、活动能量、静息能量测试。 |
| `invalid_metric` | 只有在**一个有效指标都不剩**时才会返回。查看 `field` 与 `rejected`；检查单位和范围，体脂应传 `18.5`，不是 `0.185`。 |
| 返回里出现 `skipped: ["restingHR"]` | 不是错误。当天还没有静息心率样本，快捷指令产出 `0`，服务端按「今天没有样本」跳过。同一次的步数和能量照常入库。 |
| `invalid_timestamp` | 已传入的 `timestamp` / `capturedAt` 不是有效的完整时间。重新把“当前日期”格式化为 `yyyy-MM-dd'T'HH:mm:ssXXX`，不要只填日期。 |
| `timestamp_conflict` | 同时传了多个采集时间，但它们不是同一时刻；只保留一个 `timestamp`，或确保值完全一致。 |
| `date_timezone_mismatch` | `date`、`timestamp` 和 `timezone` 对应的本地日期不一致；重新按第一节生成日期。 |
| `future_timestamp` | iPhone 系统时间快了，或格式化日期时选错变量。打开“自动设置日期与时间”。 |
| `missing_measurement_time` | 上传了体重、体脂、静息心率或最大摄氧量，但缺少对应的 `...MeasuredAt`；读取原健康样本的开始日期后再上传。 |
| `rate_limited` | 一小时请求过多；稍后再运行，并减少自动化频率。 |
| 返回成功但网页没变化 | 先确认登录的是同一账号，再点“立即读取账号最新数据”，并查看连接设备的“最近上传”。 |
| 体重每天重复或变成 0 | 没有样本时省略体重；有样本时同时发送 `weightMeasuredAt`。 |
| 睡眠明显翻倍 | 排除“卧床/清醒”和重复来源，或暂时不在快捷指令里同步睡眠。 |

## 八、启动页面卡住时

新版启动超过约 12 秒会显示 **修复缓存并重新打开**。它只移除网页程序缓存和旧 Service Worker，不会删除 IndexedDB 中的健康、饮食或账号记录。不要直接在 iPhone 设置中清除整个网站数据，除非已经确认账号云端备份完整；系统级“清除网站数据”可能同时删除本机记录。

在应用中撤销设备后，该令牌会立即失效。退出网页账号不会自动撤销快捷指令，这样网页关闭或暂时退出时自动上传仍能工作；要停止某台 iPhone 上传，请在数据页撤销对应设备。
