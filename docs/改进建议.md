# 改进建议（v2.12.0 之后）

这份是 v2.12.0 那轮排查留下的账。已经改掉的写在 CHANGELOG 和 CLAUDE.md 里，
这里只列**还没做**的，按「先做哪个」排。每条都写清楚是在哪儿看到的、
为什么算问题 —— 没有实测依据的想法不往里放。

判断标准和 CLAUDE.md 一致：**一屏只回答一个问题；同一件事不在一屏里说两遍；
有一套比例，而不是每处随手取一个数。**

---

## 一、审美（视觉与信息密度）

### A1. 份量弹层里三套控件在做同一件事 —— 建议删掉倍数那一排

打开「米饭（白米）」，从上到下依次是：

1. `小碗（150g）/ 中碗（200g）/ 大碗（300g）/ 按克输入` —— 四个胶囊
2. `− 1 小碗 ≈ 150 g +` —— 步进器
3. `0.5 小碗 / 1 小碗 / 1.5 小碗 / 2 小碗 / 3 小碗` —— 五个胶囊

第 3 排和第 2 个步进器**完全等价**：0.5/1/1.5/2/3 就是步进器按几下的结果。
三层加起来在 390px 上占掉约 450px，于是首屏几乎全是「改数字」，
而真正要看的「记下这一笔会推进到哪」得往下滚一屏。

建议：留 1 和 2，删掉 3。真要保留快捷倍数，把它并进步进器那一行的左右两侧
（`×0.5` / `×2`），别再单开一排。

### A2. 健身页三种「选择」用了三套视觉语言

同一屏上：

| 控件 | 现在的样子 |
| --- | --- |
| 身体部位 / 动作模式 | 分段控件（灰槽 + 白格浮起） |
| 胸 肩臂 背 腿 腹 | 分段控件 |
| 全部动作 / 推荐组合 | 下划线 tab（绿色下划线） |
| 器械筛选 | 文字 + `⌄`，没有容器 |

四个都在回答「我现在看哪一组」。CLAUDE.md 自己写着「互斥的选择一律用分段
控件 `.range-switch`」，后两个是例外。

建议：「全部动作 / 推荐组合」改成分段控件，和上面两排对齐；
器械筛选保持是个筛选器（它可以叠加在任一组之上），但给它一个明确的容器边界，
别让它看起来像第四种选择。

### A3. 数字和单位的间距没有统一

同一页里能数出四种写法：

- `116 kcal`、`420 kcal` —— 有空格
- `150g`、`蛋白 2.6g` —— 没空格
- `约 150 g`、`碳 51.8 g`（`diet.js:435`、`diet.js:1047`）—— 有空格
- `30 分钟`（健康数据格子，单位在独立 span 里）vs `34分钟`
  （`formatDuration`，近 7 日速览）

建议：在 `lib/utils.js` 里出一个 `unit(value, unit)`，一处定规矩
（西文单位前留空格、中文单位不留），所有拼字符串的地方都走它。
这是纯排版，不影响任何计算。

### A4. 圆角还有两套 token，值也没收干净

`:root` 里同时有 `--r-xs/sm/md/lg`（6/10/14/18）和 `--radius`/`--radius-sm`
（18/14）—— 后一套是前一套里两档的别名。CSS 里还剩 6/8/10/14/18 五个硬编码值
和 22 处 `999px`。

建议：删掉 `--radius`/`--radius-sm`，把硬编码值收进四档，
`999px` 保留（药丸不是一档尺寸，是一种形状）。字号那一轮已经这么做过一次，
照抄流程就行。

### A5. `--shadow` 在两个主题里是两种层次逻辑

浅色是 `none`（「层次靠底色对比，不靠投影」），深色却给了
`0 1px 2px … , 0 10px 30px …`。同一张卡在两个主题下遵循两条规矩。

建议：要么深色也用 none（深色下底色对比本来更强），要么把「浅色不用投影」
这条规矩改掉并写进 CLAUDE.md。现在这样是两边都不算数。

### A6. 主卡四个方框里的小数位不一致

`膳食纤维 0 /25g`、`钠 0 /2000mg`、`饮水 0 次` 都是整数，
只有 `游离糖 0.0 /38g` 带一位小数。四个并排的方框，一个和别人不一样。

建议：这一排统一取整（游离糖到克本来就没有 0.1g 的精度意义），
或者反过来都给一位。**别让同一排里有两种精度。**

## 二、功能

### B1. 「移到别的餐次」和「改克数」没有撤销

饮食删除、饮水、记录一笔、训练动作、训练组数现在都有撤销了
（`grep "label: '撤销'"` 能数出五处），但饮食记录里改餐次
（`diet.js` 的 `已移到X`）和改克数（`已更新`）没有 —— 而这两个恰恰是
最容易在滑列表时误触的：餐次是个下拉，克数是个数字框。

建议：这两处补上撤销，撤销时写回改动前的 `{ meal, grams }`。

### B2. 份量记忆只记克数，不记糖度和餐次

`store.rememberedPortion` 记住「上次这个食物记了多少克」，很好用。
但同一杯奶茶「三分糖」这种档位不记，每次都要重选；
同一样早餐食物几乎总是记到早餐，餐次也不记。

建议：把 `portionMemory` 的值从一个数字扩成
`{ grams, sugarLevel, meal }`（老数据当 `{ grams }` 读，不用迁移）。
`guessMeal()` 仍然按钟点猜，只在这个食物有记忆时才让记忆优先。

### B3. 「累计收支」长期只显示「配对数据不足」，但不说还差什么

配对日要求那天既有饮食记录、又有设备的静息与活动能量。
口径是对的（CLAUDE.md 有红线），但界面只写「没有同时记到摄入和消耗的日子」——
用户不知道是自己没记饮食，还是手表没同步。

建议：把缺的那一半点名，例如
「近 7 日有 6 天设备记录、0 天饮食记录，配对 0 天」。
数字都是现成的，只是没说出来。

### B4. 排训练计划时看不到「上次这个动作练了多少」

挑动作那一列只有名字和三条说明。要知道上次卧推推了多少，
得滚到页面最下面的「近 7 日训练记录」里翻。

建议：动作行右侧、加号左边给一行极轻的灰字
「上次 60kg × 8,8,6」，没记录就不写。数据在 `state.trainingDays` 里现成。
注意别做成第四个胶囊 —— 见 A2 和已经删掉的那批装饰性标签。

### B5. 分段控件没有 ARIA 语义

`.range-switch`、`.picker-view-switch`、`.chip-btn` 这些互斥选择目前是一排
普通 `<button>`，没有 `role="tablist"` / `role="tab"` / `aria-selected`
（`grep "role: 'tab"` 一处都没有）。读屏用户听到的是五个孤立按钮，
不知道它们是一组、也不知道现在选中的是哪个。

建议：给分段控件加 `role="tablist"` + `aria-selected`，
筛选类的（器械）用 `aria-pressed`。焦点样式上一轮已经统一过了，
这一步是把「看得见」补成「读得出」。

### B6. 导入没有断点，每次都是整份重来

`export.xml` 的流式解析本身没问题（几 GB 也扛得住），
但每次导入都从头扫一遍整个文件。常见用法是每月导一次，
其中 29 天的数据上次已经进来了。

建议：记下上次导入覆盖到的最后日期，Worker 里按 `startDate` 提前跳过
—— 中央目录和分块扫描的结构本来就支持这么做，只是现在没用上。
这条工程量最大，排在最后。

## 三、不建议做的

留一份「想过但不做」的名单，省得下次再讨论一遍：

- **人体部位图**：前后四版都不好看，原因不在画工 —— 真机上一整块胸大肌只有
  19px 宽，那个尺寸画不出能辨认的解剖形状，而它占掉 248px 高。见 CLAUDE.md。
- **全局「最近吃过」列表**：删掉是对的。真要减少打字，应该按「这一餐 × 频次」
  给三五个，而不是把全局历史搬回来 —— 后者早饭会给你昨晚的烧烤。
- **更多推荐说明**：现在三个短标签正好。五条推荐写成五段话，读完比自己翻列表还慢。
- **给热量加红色**：任何情况下都不画红。+0.3 kg/周的增重计划本来就要求吃超，
  把执行计划画成危险色是自相矛盾。
